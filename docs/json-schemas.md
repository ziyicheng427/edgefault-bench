# Versioned JSON Schemas

EdgeFault-Bench ships Draft 2020-12 JSON Schemas inside its Python wheel. They provide a
language-independent contract for task manifests, prepared feature tables, and core result
bundles, allowing external tools to validate artifacts without importing internal Python classes.

## Available schemas

```bash
edgefault schema list
```

The initial public names are:

- `task`: condition-held-out task manifest schema v1;
- `prepared-feature-table`: model-ready rows with recording and domain provenance, schema v1;
- `result`: seed-level metrics, complexity, latency, environment, and code provenance, schema v1.

The schema name selects the current packaged file for that major contract. Every file also has a
stable `$id` and an explicit `schema_version`. Breaking changes require a new versioned schema;
published v1 artifacts will not be silently reinterpreted.

## Validate artifacts

One command can validate one or more files:

```bash
edgefault schema validate --kind task registry/tasks/*.json
edgefault schema validate --kind prepared-feature-table prepared/example.json
edgefault schema validate --kind result results/example.json
```

Success produces machine-readable JSON containing the schema kind, artifact count, path, and
available identity. Failure exits before downstream execution and reports stable JSON paths such
as `$.partitions.train`.

## Structural and semantic validation

Schema validation checks portable structure and scalar constraints. It does not replace the
domain-aware safeguards implemented by the Python workflow:

- `edgefault task audit` checks recording assignment and cross-partition leakage;
- prepared-table task binding checks dataset identity, task labels, required domain fields,
  non-empty partitions, and consistent metadata for repeated recording identifiers;
- `edgefault results validate` checks the frozen seed sequence and Git provenance;
- checksum-enforced dataset acquisition checks source-file identity.

A publishable workflow should pass both the relevant schema command and semantic audit. Passing a
schema does not establish that preprocessing is scientifically appropriate, a model is accurate,
or a result is safe for operational deployment.

## Packaged-resource guarantee

Schemas live under `edgefault_bench.schema_specs` and are loaded with `importlib.resources`, not a
repository-relative path. The 2026-09-13 local build audit verified all three files in the wheel;
the upcoming distribution milestone will repeat wheel installation as a CI gate.

Repository CI validates every registered task, all v1 and v1.1 core result bundles, the synthetic
prepared-table fixture, and each result generated by the installed-plugin execution audit.
